Project Chimera: Enhanced Dead Man's Switch App Blueprint for AI Development
This document outlines the concept, design, architecture, and vision for "Project Chimera," an enhanced Dead Man's Switch web application. This blueprint is structured for processing by AI development platforms like lovable.dev or bolt.new, emphasizing key components and technical implementation details, particularly leveraging Supabase.

Project Overview Project Name: Project Chimera Core Concept: A digital Dead Man's Switch with an immersive, atmospheric, and cryptic user experience.   Goal: To create a unique and engaging digital artifact by prioritizing atmosphere and a specific dark aesthetic over conventional utility.   Target Platforms: Designed for deployment on AI-assisted development platforms like lovable.dev and bolt.new, with a strong focus on Supabase integration.  
Core Functionality Basic Principle: If a user fails to perform a specific action within a set time, a predefined payload is dispatched.   Action to Prevent Trigger: User must enter a specific, predetermined password into an unlabeled input field.   Password: The initial predetermined password is "bluemoon25".   Postponement: Successful password entry postpones the scheduled trigger by a fixed interval (initially 5 days).   Payload: Initially conceived as documents within a file named "button".   Trigger Action: Dispatch the payload via email if the password is not entered in time.   Feedback: Minimal or no explicit feedback for incorrect password input.  
User Experience: Atmosphere & Interaction Aesthetic: Dark, ominous, tech-centric aesthetic with minimal explicit context. Draws inspiration from Tech-Noir, Cyberpunk, Glitch Art, Brutalism, and Tech-Occult Symbolism.   UI: Intentionally minimal and cryptic.   Central Element: A prominent countdown timer visualizing time remaining until trigger. The timer should be visually engaging and potentially incorporate thematic degradation as the deadline nears.   Input Field: Unlabeled text input field for password entry, enigmatically placed.   Interaction Model: Framed as a ritualistic interaction rather than a standard login.   Visuals: Dark palette (dark grey surfaces), tech-noir/cyberpunk accent colors (electric blues, purples, reds), high contrast. Thematic typography (sans-serifs, monospaced fonts). Minimalist, evocative icons blending tech and symbolic motifs. Abstract, atmospheric tech-based imagery/animations. Subtle animated backgrounds. Visual degradation linked to timer.   Audio: Crucial for atmosphere and feedback. Ambient soundscape (deep electronic drone, hum). Sparse, impactful interaction sounds (blip for focus, static/growl for error, click/clunk for success).  
Technical Architecture (Supabase Focused) Backend Strategy: Supabase-centric, leveraging PostgreSQL database, authentication, file storage, and serverless Edge Functions.   Scheduling Mechanism: Utilize Supabase pg_cron to periodically invoke a Supabase Edge Function.   State Management: Dedicated Supabase table (scheduled_tasks) to store trigger timestamp, payload location, status, and postponement interval.   Postponement Logic: Edge Function invoked on successful password validation to update next_trigger_at in the scheduled_tasks table.   Payload Handling: Supabase Storage for file storage. Payload files must be encrypted before or during upload via an Edge Function. Encryption keys stored securely in Supabase Vault.   Email Sending: Scheduled Edge Function interacts with a third-party email service API (e.g., SendGrid, Mailgun) after retrieving and decrypting the payload. API keys stored in Supabase Vault.  
Security Considerations Password Handling: Server-side validation in a dedicated Edge Function. Password stored as a secret in Supabase Vault. Use constant-time comparison. Implement rate limiting on the validation endpoint.   Payload Security: Encrypt payload at rest using a strong symmetric algorithm (e.g., AES-256-GCM). Encryption keys stored in Supabase Vault. Restrict Supabase Storage access to only the authorized Edge Function via RLS policies.   Scheduled Execution Security: Securely handle API keys/secrets for Edge Function invocation within pg_cron using vault.decrypted_secrets. Apply principle of least privilege to Edge Function permissions. Validate inputs.   Audit Logging (Recommended): Log critical events (postponements, triggers, failures) in a dedicated Supabase table.  
Vision & Potential Enhancements Tiered Postponement: Introduce dynamic consequences like diminishing returns (shortening interval) or shifting keys (changing password).   Environmental Triggers/Inputs: Subtle reactivity to user's local time of day.   Subtle Lore & Easter Eggs: Embed hidden messages, symbols, or use key combination triggers to reveal lore snippets or access logs.   Gamified Elements (Subtle): Light game mechanics like a consecutive postponement counter or 'achievement' unlocks.   Goal: To move beyond a simple utility and become a thought-provoking piece of interactive art.

I've implemented Project Chimera, a Dead Man's Switch application with a dark tech-noir aesthetic. The application features a prominent countdown timer that visually degrades as the deadline approaches, an unlabeled password input field for verification, and ambient audio to enhance the atmospheric experience.

The project is built with React, TypeScript, and Tailwind CSS, with animations powered by Framer Motion and audio handled by Howler.js. The backend integration is prepared with Supabase, including database tables for scheduled tasks and Edge Functions for password validation and task processing.

The interface follows the requested minimal, cryptic design with intentional obscurity while maintaining functionality. The visual state changes dynamically as the countdown progresses, introducing glitch effects and color shifts that intensify as the deadline approaches.

To use the application, simply enter the password "bluemoon25" in the input field to postpone the scheduled task by the default 5-day interval.
